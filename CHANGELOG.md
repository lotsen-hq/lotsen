# Changelog

The notable changes in each release of lotsen, newest first. Versions follow [semantic versioning](https://semver.org/), as [`docs/versioning.md`](docs/versioning.md) describes.

## Unreleased

### Added

- **Codebase tours of Azure DevOps and GitHub repositories, and of any public https git repository.** Ask Claude to "tour this repository" in a checkout, or run `/lotsen:tour-repo` with a repository's URL and a branch, tag or commit, for one of three purposes. An orientation shows what each area of the code is for, its vocabulary and its main paths. A tour to prepare a change walks the part that you name: its boundaries, its callers, its constraints and the tests that pin it, with risk stops where a change would ripple. An evaluation walks the design and its weak spots, with risk and question stops, and asks checks where your judgment matters. Claude reads the code at the tour's commit, from your checkout or from a worktree or a temporary clone that it offers to make, instead of switching your branch. It keeps an orientation to about 20 stops, a tour to prepare a change to about 15 and an evaluation to about 25, unless your words ask for a thorough or a quick tour. Every area gets at least one stop, and the overview names the areas that it passes over lightly, with Re-plan… to cover one in depth in the tour and Dive… for a tour of its own. A stop can name the traps in its code and a small experiment to try. The top bar shows the tour's title, repository and ref, and the Files panel shows the whole repository, with markers on the files and folders that the tour visits. Claude reports text in the code that tries to steer it, in the terminal and in the tour, and does not follow it. Summarize asks Claude for the synthesis that the purpose calls for: a map of the code to keep, a change plan or a judgment. Each lists your sent typed notes as your findings. A codebase tour has no Draft PR comments, and Draft work items asks you first where the work items belong: your own project or the tracker of the project that the tour shows. A repository on another host works through its `https` clone URL, with git alone and no sign-in, so lotsen refuses a private one there. Its mentions of work items and pull requests show as text.
- **A codebase tour's Files panel opens on the files that the tour visits.** Its Visited view lists each file that a stop's code passages or links point into, with a marker that counts the stops that visit it, and opens the file at the tour's commit. As in a pull request's tour, you can show the files as a tree or a flat list, Group by stop lists the open stop's files first under This stop, and Dim other files dims the rest. A dive's files show in the dive, not in the tour it came from. Repository beside Visited shows the whole repository with the same markers.
- **Dive into part of a codebase tour.** Dive… in the Stop panel's Ask Claude menu asks Claude for a new tour of that stop's code, and Dive… in the Plan panel's ⋯ menu asks for one of what your words name. You pick the dive's purpose and familiarity level, and your words are optional for a stop. Claude writes the dive at the same commit as the tour it came from, from the same checkout, worktree or clone, and keeps it to the part that you asked about. A dive's top bar shows a breadcrumb back to the first tour, and each step opens its tour. The tour it came from lists its dives with their reading state in a Dives row on their stop, a marker in the Plan panel and a Dives section on the summary page. The tour list and the switcher group the dives under the first tour. An overview that names areas it passes over lightly points you at Dive…. A pull request's tour offers no dive. Deleting or archiving a tour takes its dives with it, and their dives too. Unarchiving it restores the dives archived with it, and a dive that you archived on its own stays archived.
- **Find the open file in the Files panel.** Reveal the open file in the panel's toolbar opens the folders that hold the file in the current view and scrolls to it, and when the view does not list the file, it shows the file in the Repository view at its side. Collapse all closes every folder of the current view. Following a link to code in a stop, a reply or the summary page, or opening where a thread was asked, reveals the file the same way, but only in the view that shows, which it never changes. The keyboard focus stays where it was, and Tab enters the tree at the revealed file.
- **Move a codebase tour and its dives to the latest commit of its branch.** The top bar shows the commit that a codebase tour is at, and Move… beside it when the tour follows a branch, the default branch included. A tour at a tag or a commit shows only its commit. Move… checks the branch and shows the tour's commit and the branch's latest one, with the tour's dives that are behind it, all ticked and nested as in the family. Unticking a dive unticks its dives, and ticking a dive ticks the dive it came from. The move takes the tour and the ticked dives to the latest commit, and each stop whose code changed shows as stale since the move, such as "Stale since move 1", until Claude revises it. Claude hears of the move in each moved tour and revises its stale stops. A move needs a Claude session attached to each moved tour that has a stale stop, and when the branch moved on since the check, Move… says so and checks again. lotsen does not watch a branch for new commits, so Move… is where you learn of them, and a moved tour shows only its new commit, with no diff to the old one.
- **Give a note a type.** The ask box and a note's thread view offer a type: decision, concern or open question. The ask box gives it to the note that you save or the question that you send, and the next one starts without a type. The summary page lists a typed note under Decisions, Concerns or Open questions, marked as your note and linked to its thread, whether the thread is open, resolved or outdated. Claude still sees no note until you send it. A sent note keeps its type, and the summary page then marks it as your finding. Once sent, Claude sees the type when it fetches the question and in the review summary, so it reads the note as the decision, concern or open question you filed. A question that you send with a type holds it as a sent note does. The view of a sent question offers its type too, and you can change it at any time without sending Claude anything new.
- **The summary page's follow-ups take your typed threads.** Draft work items takes the sent threads of type decision, the open questions follow-up those of type open question, and Draft PR comments those of type concern, beside the sent answers. A follow-up is available when its group holds only such a thread. For an open question thread, Claude adds to that thread instead of starting a new one. An outdated thread never goes, and neither does a concern or an open question that you resolved, so a follow-up that you send again after such a change, or after you delete one of its threads, is refused. When you ask Claude in the follow-up's thread to do the work again, Claude skips such a thread and says which ones it skipped. Claude reads each as your own finding, and a synthesis lists it as yours. A note that you have not sent never goes to Claude.
- **lotsen 0.3.0 and earlier cannot read a tour that this version writes, a pull request's tour included.** This version writes every tour in a new layout, whatever it holds. The earlier versions leave such a tour out of the tour list, and their prune of clones can remove its clone. No tour is lost: this version reads it and clones its repository again when it needs to. This version still reads the tours that 0.3.0 wrote.

### Changed

- **The pull request tour skill is now `/lotsen:tour-pr`, so `/lotsen:tour` no longer works.** Run `/lotsen:tour-pr` with the pull request's URL instead, or ask Claude to tour a PR in words, as before.
- **Claude does not redo a reorder or a decision that the tour has moved past.** When you ask in the thread of a reorder, a familiarity change, a plan approval or an iteration update for the work again, lotsen tells Claude whether the tour moved past it: the plan's stops changed since the reorder or the approval, you changed the familiarity level again, or the tour moved to another update. Then Claude declines the work, says why and what you can use instead, such as Re-plan… or Reorder… in the Plan panel, and still answers your question. A plan approval's stops now follow the familiarity level that the tour holds when Claude writes them.
- **A stop's links to code count as its files.** The Files panel's Group by stop lists a changed file that a stop names only through a link in its text under This stop, and Dim other files leaves it undimmed. A codebase tour's markers count such a file and its folders too. A stale stop's links count only on a side where one of its code passages is still at the tour's commit.
- **The ask box's Save as note button shows a save icon**, so it no longer looks like a button that adds an attachment.

## v0.3.0 - 2026-11-15

### Added

- **Tours of GitHub pull requests.** Start a tour from any github.com URL of a pull request, such as its changed files. lotsen reads the pull request with your GitHub CLI sign-in, which `gh auth login` sets, also for a public repository. When the pull request's head changes, lotsen offers the new iteration, numbering the heads it sees from 1. lotsen shows a merged pull request as completed and a closed one as abandoned, and links mentions of issues and pull requests to GitHub. GitHub Enterprise Server and GHE.com are not supported.
- **Choose the size of the page's text.** Settings offers Small, Medium and Large, and the code in the diffs scales with the rest. Medium keeps the sizes of earlier versions.
- **Choose a color theme.** Settings offers Catppuccin, Visual Studio Code and Gruvbox beside Lotsen's own colors. Each has a light and a dark palette, so the Theme setting still picks light, dark or the system's choice.
- **Catppuccin and Gruvbox syntax colors** join the Syntax colors setting. It stays separate from the color theme, so you can combine any two.

### Changed

- **A tidier Settings panel.** The settings sit under Appearance, Tour, Threads and Storage. Color theme and Syntax colors are dropdowns that show each family's colors, Placement and Thread messages show a small picture of each choice, and a preview shows the chosen colors and font size on a few diff lines. Mixed threshold shows only while Placement is Mixed, and the panel's footer shows the lotsen version.
- **A diff line with thread markers is as tall as any other line**, so its code sits level with its line number.
- **A stop's checks are easier to read.** Each check sits in its own card under its question in bold, with a pill that says whether it needs an answer or how far its answer has come, and the Checks heading counts the answered checks. Claude's recommendation shows in Claude's colors, and folds once you answer the check. Fewer labels stand between the question and the suggestions, and the answer type menu is as large as the buttons beside it.
- **The top bar's controls share one height and one look for each kind.** The tour switcher's chevron has no border, the Claude session state is a pill, and the pull request label shows its link with an underline and an external-link mark. Thin dividers split the bar into the tour, the stop, and Claude and the workspace. The tour takes only the width it needs, so the stop line shows more of the stop's title, and the update check sits beside the pull request label. When the stop line runs short of room, the chapter gives way before the stop's title, and "Skipped" stays. "Send answers" shows the unsent count inside the button, and a refused send shows its reason in a strip under the bar until you dismiss it. One status chip shows the Claude session, turns amber while the page connects or reconnects, and lists the session, the connection and Claude's current work on a click, so the bar no longer shows "Live" or "No Claude session is writing this tour". While a plan waits for your approval, the bar shows a "Review the plan" button that opens the Plan panel, brings a popped-out Plan panel's window forward where the browser allows it, and moves the focus to "Approve plan". In a narrow window the bar gives way in a fixed order, down to 720px at every font size, so its controls stay in the window.
- **The keyboard focus is easier to see in the light theme.** A focused button's edge takes the primary color, so it stands out against every surface a button sits on, in every color theme.
- **Gray text in the light theme is darker**, so small labels such as a thread's "Resolved" read clearly on their gray fill.
- **Stops and diffs load faster, most of all on Windows, where each git process is slow.** lotsen keeps what git told it about a tour's commits in its git fact cache, so a stop that Claude writes again, a diff you open again and the list of changed files after pinning start no git process. The first stop that Claude writes on a pin starts fewer of them too.

## v0.2.0 - 2026-11-13

### Added

- **Dockable panels.** Drag a panel to any side of another, or into a group of tabs. The layout is saved and comes back on the next load. The Panels menu applies a ready-made arrangement (Default, Columns, or Explanation above the diff), saves and applies your own named layouts, and resets the layout.
- **Pop a panel out into its own browser window.** Closing the window returns the panel to its place among its group's tabs. lotsen tells you when the browser blocks the window.
- **Preferences apply in every open tab.** The page's preferences, your named layouts among them, live in lotsen's data directory, so a change applies at once in each tab and survives a change of port.
- **Mark a stop as done** from the Plan panel or the Stop panel. Once Claude revises the stop, the plan shows it as done on an earlier version.
- **Parts fold a large tour's chapters.** Claude can group the chapters of a large tour into parts, and the Plan panel folds each part to its heading.
- **Mentions of work items and pull requests in a tour link to Azure DevOps.**
- **The tour's label in the header links to its pull request.**

### Changed

- **The Stop panel's controls sit in one toolbar under the title:** an Ask Claude menu, the done checkbox, the skip toggle and a menu with the placement and the version choice.
- **Panels no longer fold.** Each group's header maximizes or hides its panel, and the Panels menu in the top bar hides and shows each panel. Files and Plan are separate panels.
- **`lotsen open` says why the server refused it**, and names both builds when the server runs another build of lotsen.
